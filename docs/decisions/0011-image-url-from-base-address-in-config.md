# 11. Адресът на снимка се сглобява от основен адрес в `config.json`

Дата: 2026-11-08
Статус: прието

## Контекст
API връща за снимките само `storageKey` – ключ във файловото хранилище, не адрес (`docs/data-model.md`). Магазинът трябва да покаже снимка на продукт, а място, което сервира файловете, още няма (хостингът и хранилището не са избрани).

Разгледани са три пътя: основен адрес в `config.json`, ендпойнт в API (`/api/v1/media/{key}`) и временен вграден адрес за демото. Вторият променя договора на API и натоварва API с файлове, третият вгражда адрес в кода.

## Решение
- `config.json` получава по избор поле `imageBaseUrl`. Адресът на снимка е `imageBaseUrl` + `/` + `storageKey` (всяка част от ключа се кодира за адрес).
- Единственото място, което сглобява адреса, е `imageUrl` в `@storefront/shared`. Компонентите получават готов `url` и не знаят откъде идва.
- Ако `imageBaseUrl` липсва, `url` е `null`, а магазинът показва снимка по подразбиране (`ImagePlaceholder`). Същото става и когато снимка не се зареди.
- Смяна на хранилището (CDN, S3, ендпойнт в API) е промяна на `imageBaseUrl` или само на `imageUrl`, без да се пипат компоненти.

## Последствия
- API не се променя.
- Докато няма хранилище и демо снимки, в магазина се вижда само снимката по подразбиране. Демо снимки са отделна задача.
- Всяка среда задава `imageBaseUrl` в своя `config.json`.
