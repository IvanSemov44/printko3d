# 10. TanStack Query за слоя с API заявки и генерирани типове от OpenAPI

Дата: 2026-11-07
Статус: прието

## Контекст
`CLAUDE.md`, раздел „Frontend“, определя RTK Query като единствен слой за API заявки. Собственикът не държи на него: за заявките той изисква Redux store, който магазинът иначе не ползва. Задача 06 е първата, която чете данни от API, затова изборът се прави сега.

## Решение
- Слоят за API заявки в `storefront` (и по-късно в `admin`) е TanStack Query (`@tanstack/react-query`, лиценз MIT).
- Типовете на отговорите се генерират с `openapi-typescript` (MIT, само за разработка) от OpenAPI документа на API. Документът е записан в `src/web/shared/openapi.json`, а генерираният файл `src/web/shared/src/api/schema.d.ts` е в репото. Прегенерира се с `npm run api:types` в `src/web/shared`, след като `openapi.json` се обнови от `/openapi/v1.json` на работещо API в среда `Development`.
- Маршрутизацията е с `react-router` (MIT).
- Заявките минават през малък общ клиент в `@storefront/shared`, който връща `ApiError` с кода от `ProblemDetails`.

## Последствия
- Няма Redux в магазина. Кешът, повторният опит и състоянията за зареждане и грешка идват от TanStack Query.
- Ръчно писани типове на отговорите не се допускат. Ако API промени договора си, `schema.d.ts` се прегенерира и TypeScript показва къде кодът е счупен.
- OpenAPI документът се издава само в среда `Development`, затова снимката в репото се обновява ръчно при промяна на договора на API.
- Редът за RTK Query в `CLAUDE.md` вече не отговаря на това решение. Текстът в `CLAUDE.md` се поправя с отделна промяна, одобрена от собственика (задача 06 не го пипа).
