# Backend: правила за `Application` и `Infrastructure`

Допълва [0017](../decisions/0017-api-structure-and-style.md), който покрива само `Storefront.Api`. Тук са правилата за двата слоя под него. Къде стои кой файл е в [architecture.md](../architecture.md), защо са избрани слоевете е в [0006](../decisions/0006-book-style-layers-and-controllers.md), а какво вземаме и какво сменяме от книгата е в [0008](../decisions/0008-code-style-reference-book.md). Тук те не се повтарят.

**Как се чете.** Всяко правило е с отговор „да“ или „не“. Колоната „Днес“ казва дали кодът го следва; „не“ е ред в [tech-debt.md](../tech-debt.md), не скрито правило. Правилата за стила на самия C# (именуване, `null`, `async`) са в [csharp-golden-rules.md](csharp-golden-rules.md) (правила CC1–CC27).

**Източници.** [Efficient Querying](https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying), [Pagination](https://learn.microsoft.com/en-us/ef/core/querying/pagination) и [Applying Migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying) на EF Core; [Task asynchronous programming](https://learn.microsoft.com/en-us/dotnet/csharp/asynchronous-programming/task-asynchronous-programming-model); „Ultimate ASP.NET Core Web API“ на Code Maze (гл. 5–6 за услуги и изключения), през 0008.

## Общи правила за бекенда (преместени от `CLAUDE.md`)

Решение [0021](../decisions/0021-claude-md-handbook-and-hooks.md) премести тук таблицата „Backend“ от `CLAUDE.md` без промяна в смисъла. Правилата B1–B28 по-долу ги разширяват и не ги отменят.

Структурата е прост модулен монолит с четири проекта: Domain, Application, Infrastructure и Api. Не се ползват CQRS и външна библиотека за посредник, докато няма реална нужда от тях. Ентитата са прости класове, достъпът до данни е през repository-та и `IRepositoryManager`, а правилата на модела са в услуги на Application; API е с контролери (решение [0006](../decisions/0006-book-style-layers-and-controllers.md)).

| Тема                | Правило                                                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Зависимости         | Domain не зависи от нищо. Api не говори директно с `DbContext`, а през услуги на Application                                                               |
| Версия и компилатор | Текущата LTS версия на .NET, включени nullable reference types, предупрежденията са грешки                                                                 |
| API                 | REST под `/api/v1`, OpenAPI документация, еднакъв формат за страниране във всички списъци                                                                  |
| Структура на API    | Структура на `Storefront.Api` и стил на контролерите: решение [0017](../decisions/0017-api-structure-and-style.md) и [architecture.md](../architecture.md) |
| DTO                 | Entity обектите никога не се връщат от API. Картографирането е явно или в самата заявка                                                                    |
| Асинхронност        | Целият път е `async`, а всяка операция приема и подава `CancellationToken`                                                                                 |
| Валидация           | Входът се валидира на границата на API. Инвариантите на модела се пазят в услугите на Application, а тези, които могат, и в базата                         |
| EF Core             | Конфигурация в отделен клас за всеки обект, без lazy loading, за четене `AsNoTracking` и `Select` към DTO, без N+1 заявки                                  |
| Миграции            | Влизат в репото, имат смислено име и се прилагат върху чиста база в CI. Не се редактират след merge                                                        |
| Ограничения         | Уникалността и външните ключове се налагат в базата, не само в кода                                                                                        |
| Списъци             | Винаги със страниране и максимален размер на страницата                                                                                                    |
| Грешки              | Формат `ProblemDetails`, без stack trace в продукция, без прихващане на всички изключения                                                                  |
| Логове              | Структурирани, с идентификатор на заявката, без лични данни и тайни                                                                                        |
| Конфигурация        | Options pattern и променливи на средата. Настройките на магазина идват от таблицата, не от кода                                                            |
| Нови пакети         | Само след одобрение. Предпочита се вграденото в .NET, а за всеки пакет се проверява лицензът и поддръжката                                                 |
| Стил                | `.editorconfig`, форматиране в CI, без закоментиран код и без `TODO` без свързана задача                                                                   |

## Услуги (`Application/Catalog/Services/`)

| №   | Правило                                                                                                                                                                                                                  | Как се проверява                                                                                                          | Образец                                | Днес                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------- |
| B1  | Една услуга отговаря за една област (`CategoryService`, `ProductService`, `StoreSettingsService`). Услугата не вика друга услуга; общото е в статичен `*Rules` клас или в `ServiceManager`                               | Конструкторът приема само `IRepositoryManager` и интерфейси от `Contracts/` (като `IImageStorage`), не друга услуга       | `CategoryService`                      | Да                                              |
| B2  | Файлът на услугата е до **300 реда** или до **12 публични метода**. Над това се дели по подобласт (например снимки и варианти на продукт) и се записва в `tech-debt.md`, докато не се раздели                            | `wc -l` на файла; броят на `public` методите                                                                              | `CategoryService` (188 реда)           | **Не**: `ProductService` е 444 реда и 18 метода |
| B3  | Правилото за полетата, което не иска база, е в статичен клас `*Rules` до услугата (`ProductRules`, `VariantRules`, `ImageRules`, `SlugRules`). Така се тества без `FakeRepositoryManager`                                | В `*Rules` няма `IRepositoryManager`, `await` или `DbContext`                                                             | `ProductRules.Validate`                | Да                                              |
| B4  | Грешките по полетата се събират в `FieldErrors` и се хвърлят заедно (`ThrowIfAny`). `Guard` е за една проверка на един параметър                                                                                         | Търсене: няколко последователни `throw new ValidationFailedException` в един метод означава, че трябва да е `FieldErrors` | `ProductRules.Validate`                | Да                                              |
| B5  | Проверка за съществуване или заетост е **частен помощен метод** със смислено име (`EnsureSlugIsFreeAsync`, `EnsureCategoryExistsAsync`, `FindAsync`). Не се повтаря `repo.Get… ?? throw` на две места (книгата, гл. 5–6) | В услугата няма два еднакви реда `?? throw new NotFoundException` с един и същ код                                        | `ProductService.EnsureSlugIsFreeAsync` | Да                                              |
| B6  | Всяка промяна на ред с версия започва с `repositories.X.ExpectVersion(entity, input.Version)`, преди да се променят полетата (решения 0016 и 0019)                                                                       | Всеки метод, който взема `Update…`, вика `ExpectVersion`                                                                  | `CategoryService.UpdateAsync`          | Да                                              |
| B7  | Услугата записва веднъж, в края: един `repositories.SaveAsync(cancellationToken)` на операция                                                                                                                            | В метода има един `SaveAsync` (изключение: запис, който трябва да мине преди или след външен ефект, с коментар защо)      | `CategoryService.CreateAsync`          | Да                                              |
| B8  | Услугата не връща `Entity` към `Api`. Връща `Guid` (при създаване), нищо (при промяна) или DTO                                                                                                                           | Подписите на публичните методи на интерфейса                                                                              | `ICategoryService`                     | Да                                              |

## Входни модели, DTO и грешки

| №   | Правило                                                                                                                                                                                                                                                  | Как се проверява                                                                                                                                      | Образец                                                                             | Днес |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ---- |
| B9  | Входът на услугата е `record` в `Catalog/Inputs/`, един тип на файл, с име `New…` или `Update…`. Промяната носи `Version` (`uint`), ако обектът има версия                                                                                               | Папката; `Update…` на обект с версия има `Version`                                                                                                    | `Inputs/UpdateCategory.cs`                                                          | Да   |
| B10 | Това, което излиза от API, е `record` в `Catalog/Queries/` с име `…Dto`. Страниците са `PagedResult<T>`; параметрите на списък имат максимален размер на страницата, който се пази на сървъра                                                            | Папката; в параметрите на списък има `MaxPageSize`                                                                                                    | `ProductListQuery.MaxPageSize`                                                      | Да   |
| B11 | Грешката на домейна е едно от петте изключения в `Exceptions/` (`NotFound`, `Validation`, `Conflict`, `FileRejected`, `InvalidCredentials`). Нов тип се добавя само заедно със запис в `ApiExceptionHandler`                                             | В `Application` няма `throw new Exception(` и няма `catch`, който поглъща грешка: допустим е само `catch` за почистване, който хвърля `throw;` отново | `ConflictException`; допустим `catch` с `throw;`: `ProductService.UploadImageAsync` | Да   |
| B12 | Код на грешка: `<обект>.<причина>` с малки букви и долна черта (`product.slug_taken`, `variant.sku_taken`, `category.version_conflict`). Кодът е договор с клиента: не се преименува, без да се обнови `openapi.json`, коментарът на адреса и фронтендът | Търсене на кода в `Api/Controllers/*` (коментар `remarks`) и в `shared/src`                                                                           | `SaveErrorTranslator`                                                               | Да   |
| B13 | Конфликт, който може да се види и в базата (уникален индекс), се налага **и в двете места**: услугата проверява рано и дава ясна грешка, базата е последната защита, а `SaveErrorTranslator` превежда нарушението към същия код                          | За всеки `Ensure…IsFree…` има запис в `UniqueIndexes` и тест в `CatalogConstraintTests`                                                               | `EnsureSlugIsFreeAsync` и `IX_products_slug`                                        | Да   |

## Достъп до данни (`Infrastructure`)

| №   | Правило                                                                                                                                                                                                                                                                                                                 | Как се проверява                                                           | Образец                                     | Днес             |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------- | ---------------- |
| B14 | `IQueryable` не излиза извън `Infrastructure`. Repository връща обект, списък или `bool`; четенето за екран е в `CatalogQueries` и връща DTO                                                                                                                                                                            | `Contracts/` няма `IQueryable`                                             | `ICatalogQueries`                           | Да               |
| B15 | Четене за екран: `AsNoTracking` (идва от `Query(trackChanges: false)`) и `Select` директно към DTO. Без `Include` за четене и без заявка в цикъл (N+1)                                                                                                                                                                  | В `CatalogQueries` няма `Include(` и няма `await` в `foreach` над резултат | `CatalogQueries.GetProductsAsync`           | Да               |
| B16 | Списък е със страниране в базата (`Skip`, `Take`, `Count`) и с максимум, не `ToList` и срязване в паметта. Страниране с `Skip` е по решение 0008; ако списък нарасне до хиляди редове, преминаването към keyset страниране ([Pagination](https://learn.microsoft.com/en-us/ef/core/querying/pagination)) е ново решение | Всяка заявка за списък вика `Take` и има горна граница                     | `GetAdminProductsAsync`                     | Да               |
| B17 | Заявките за четене са в `CatalogQueries` до **300 реда**. Над това се дели по тема (магазин, админ продукти, админ категории) в нови класове, зад същия интерфейс или нов                                                                                                                                               | `wc -l`                                                                    |                                             | **Не**: 375 реда |
| B18 | Всяка конфигурация е отделен клас `IEntityTypeConfiguration<T>` в `Persistence/Configurations/`. Дължини, `IsRequired`, индекси, външни ключове и `OnDelete` са там, не в атрибути на `Domain`                                                                                                                          | Домейнът няма атрибути на EF; всяко `string` свойство има `HasMaxLength`   | `CategoryConfiguration`                     | Да               |
| B19 | Външен ключ има явно `OnDelete`. По подразбиране е `Restrict`; `Cascade` се ползва само ако детето няма смисъл без родителя (снимка без продукт), с коментар                                                                                                                                                            | Търсене на `HasForeignKey` без `OnDelete`                                  | `CategoryConfiguration` (`Restrict`)        | Да               |
| B20 | Имената в базата са в `snake_case`, таблиците са в множествено число (`categories`, `product_variants`). Индексите по подразбиране на EF (`IX_<таблица>_<колона>`) се оставят; нарочно именуван индекс (частичен, с условие) е `ux_<таблица>_<какво>`                                                                   | `database-schema.md` и `ToTable(...)`                                      | `ux_product_images_one_primary_per_product` | Да               |
| B21 | Парите са цели числа в най-малката единица (`long`/`int`), никога `decimal` с закръгляване в услугата                                                                                                                                                                                                                   | Търсене на `decimal` в `Domain` и `Application`                            | `ProductVariant.Price`                      | Да               |

## Какво не е тук

- Именуване на методи и типове, `async`, `null`, логове и изключения като стил на C#: [csharp-golden-rules.md](csharp-golden-rules.md).
- Кога се пишат тестовете и как: [testing.md](testing.md) и `test-writing-rules.md` (16d-3).
- Съгласуваност и индекси по-подробно, решения и граници между проекти: [architecture-and-data-rules.md](architecture-and-data-rules.md) (AD1–AD29).
- Ред на работа за цяла функционалност: [new-feature.md](new-feature.md).
